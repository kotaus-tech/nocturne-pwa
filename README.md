# NOCTURNE

**Личные миры. Живые истории.**

Локальное PWA-пространство для ролевых историй с AI: персонажи с характерами и
предысторией, длинные диалоги с памятью, дневники персонажей, лорбук мира и
инструменты режиссёра сцены.

Всё хранится только в браузере пользователя (IndexedDB). Облака, аккаунтов и
телеметрии нет: приложение уходит в сеть ровно один раз — за ответом выбранной
вами языковой модели.

---

## Возможности

- **Персонажи** — библиотека с поиском, тегами, жанрами, закреплением и избранным;
  редактор с лорбуком, стартовыми шкалами отношений и первым сообщением;
  два независимых AI-генератора: классический (теги и своя задумка) и
  расширенный **Character DNA (V2)** — кнопка «Character DNA» в библиотеке и в
  редакторе. V2 собирает глубокого современного взрослого персонажа по модели
  «предпочтения → blueprint → персонаж»: слои личности (публичный/личный/
  уязвимый), настоящие недостатки и противоречия, быт, многослойная речь,
  отдельная модель отношений, контекстный 18+ профиль. Ответ модели проходит
  строгую валидацию схемы с одним коррекционным повтором; готовый blueprint
  сохраняется в карточке (`blueprintV2`), поддерживает частичную
  перегенерацию секций и память разнообразия. Персонажи старого генератора
  и старые сохранения работают без изменений; импорт/экспорт `.json`
  и карточек Character Card (см. раздел ниже).
- **Поиск по всему миру** — строка «Найти в моём мире» в шапке (или ⌘K / Ctrl+K)
  ищет одним запросом по персонажам, веткам, репликам, мирам (лорбукам),
  дневникам и памяти, показывая кусок текста вокруг совпадения.
- **Диалоги** — ветки на персонажа, свайпы-перегенерации, редактирование реплик,
  откат истории назад, «Продолжить» (продолжение текущей сцены), подсказки вариантов
  ответа, проверка судьбы (dice), OOC-режим.
- **Групповые сцены** — 2–4 персонажа в одной истории. Собрать сцену можно из
  библиотеки (кнопка «Групповая сцена» в карточке персонажа или над списком
  героев) или сгенерировать AI сразу с общим опенингом (режим «Группа 2–4»
  в генераторе). За ход отвечает один персонаж: адресат выбирается кнопками
  над строкой ввода, иначе его подбирает лёгкий запрос к модели по репликам
  и связям в группе, а при сбое — упоминание по имени и ротация. «Продолжить»
  передаёт ход следующему, у каждого героя свои шкалы отношений, свои мысли
  и свои перегенерации. Кто в кадре, а кто за кадром — тумблер в панели
  режиссёра и мини-бар в шапке ветки; отсутствующие в промпт попадают только
  с причиной, говорить за них запрещено. За кадром герой не застревает: в
  промпте есть блоки «Возвращение в сцену» и «Уход из сцены»: модель сама
  вводит персонажа обратно, когда это уместно по сюжету (мета-поле `returned`,
  в локальном протоколе — тег `<returned names="Имя" />`), и так же сама
  уводит его за кадр с причиной (поле `left`, тег `<left names="Имя" />`) —
  чат применяет это и показывает тост. Режим «Живая сцена» (тумблер в панели
  режиссёра) разрешает отвечающему герою добавить 1–2 короткие реакции
  остальных в той же реплике. Связи между героями не статичны: модель
  обновляет их по ходу сцены (мета-поле `relations`, тег `<relation … />`), а
  панель режиссёра помечает такие строки. В «Аналитике отношений» —
  переключатель участника.
- **Шкалы отношений** — доверие, привязанность, близость, напряжение, конфликт;
  динамический статус связи, тосты о переломных моментах.
- **Память** — фоновое извлечение фактов, авто-синопсис, тайные дневники
  персонажей, «хроника эпизодов» по всей истории.
- **Режиссёр** — заметки к сцене, режимы саспенса и динамических событий, живая
  разговорная речь, темп slow burn, выбор вектора скрытых мыслей, обои сцены.
- **Персоны** — несколько собственных личностей (имя, аватар, описание): можно
  создавать, дублировать, переключать и удалять. Кто ведёт сцену, определяется
  по цепочке: выбор в ветке чата → выбор в карточке персонажа → активная
  персона. Переключатель живёт в левой панели.
- **Промпт-студия** — сборка английских промптов для моделей генерации
  изображений: персонаж как якорь внешности, контекст сцены из последнего
  сообщения, стиль, свет, настроение, оптика, формат, детали обстановки и
  негативный промпт. Есть поиск по персонажам. Собирается локально и мгновенно,
  кнопка «Улучшить моделью» переводит черновик в чистый английский.
- **Novel Mode** — чтение истории как книги.
- **Атмосфера** — процедурный эмбиент (дождь, ветер, лес, костёр) на Web Audio,
  без единого аудиофайла.
- **PWA** — установка на устройство, офлайн-работа, обновление по уведомлению,
  защита хранилища от автоматической очистки.

## Стек

React 19 · TypeScript · Vite 7 · Tailwind CSS 4 · Dexie (IndexedDB) ·
framer-motion · lucide-react. Сборка — single-file HTML. Edge-функция Netlify для
проксирования запросов к API провайдера.

## Быстрый старт

```bash
npm install
npm run dev        # http://localhost:5173
```

Проверка типов и сборка:

```bash
npm run typecheck  # tsc --noEmit
npm run build      # проверка типов + dist/index.html (single-file)
npm run preview    # локальный просмотр прод-сборки
```

`npm run build` сначала прогоняет проверку типов: ошибка типов останавливает
сборку.

## Настройка подключения к модели

Настройки → **Модель и API**. Поддерживаются:

| Режим | Что указать |
|---|---|
| OpenAI-совместимый (`openai`) | Base URL провайдера, ключ, модель. Работает с Ru-OpenRouter, DeepSeek, OpenRouter, Ollama, LM Studio |
| Google Gemini (`gemini`) | API-ключ Gemini, модель выбирается из списка |

Есть готовые шаблоны подключений, сохранение своих пресетов, загрузка списка
моделей с сервера, тонкая настройка сэмплинга и режима размышлений.

Рядом с полем модели — кнопка **«Проверить соединение»**: короткий запрос к
модели тем же путём, что и обычная генерация (включая резервный прокси).
Показывает ответ модели и время отклика, а при сбое — понятную причину
(ключ, лимит, CORS и прокси); долгий запрос можно отменить той же кнопкой.

**RU OpenRouter** (`https://api.ru-openrouter.ru/v1`) — отдельный шаблон в
настройках. Если в адресе указан только хост, путь `/v1` дописывается сам:
без него сервис отвечает 404. Провайдер не пускает браузер напрямую (CORS),
поэтому запрос автоматически уходит через same-origin канал `/api/llm-proxy`, не вызывая прямую CORS-ошибку браузера.

Для локальных моделей (Ollama/LM Studio) запустите сервер с разрешёнными
источниками, например: `OLLAMA_ORIGINS=* ollama serve`.

## Карточки персонажей (Character Card)

NOCTURNE понимает открытый формат карточек, который используют SillyTavern,
Risu, Chub и JanitorAI. Можно перенести героя из другого клиента или, наоборот,
отдать своего.

| Что | Как |
|---|---|
| Импорт | Кнопка «Импорт персонажа» в библиотеке (или перетащите файл на окно). Поддерживаются `.json` карточки **V1 / V2 / V3** и PNG с вложенной карточкой |
| Откуда берётся аватар | Из PNG — сама обложка файла (сжимается до 512 px); из V3 — иконка из `assets` |
| Что переносится | имя, описание, характер, сценарий, системный промпт, первое сообщение, теги, мир (`extensions.world` → жанр), лорбук (`character_book`) |
| Альтернативные приветствия | `alternate_greetings` сохраняются и становятся **свайпами первого сообщения** новой ветки |
| Примеры реплик и инструкции | `mes_example` и `post_history_instructions` складываются в системный промпт отдельными секциями, повторный импорт не дублирует их |
| Заметки автора | `creator_notes` становятся подписью персонажа |
| Чистка мусора | Текст приводится в порядок автоматически: HTML-вёрстка, markdown-картинки, невидимые символы и мусорные `\n` убираются; `{{user}}` и `{{char}}` заменяются на имя персоны и персонажа; changelog, реклама и ссылки на Discord/Google Диск/Chub выбрасываются; примеры диалога переезжают из системных правил в примеры |
| Лист персонажа блоками | Карточки с Chub и Wyvern хранят всё в одном поле: `[Personality: …] [Backstory: …]`. Такие блоки разбираются и раскладываются по полям: внешность и тело — в описание, характер и манера речи — в характер, предыстория и цели — в сценарий, `[Genre]` — в жанр и теги, `[Age]` — в возраст |
| Если чистка не нужна | В окне импорта есть тумблер «Очищать текст карточки»; рядом показывается отчёт: сколько блоков разложено, сколько служебных абзацев выброшено |
| Экспорт | В карточке персонажа: «Карточка V2 (.json)» — файл для любого клиента; «Карточка в PNG» — карточка вложена в PNG с текущим аватаром (чанк `chara`, base64), файл можно перетащить прямо в окно персонажей |

Свой формат никуда не делся: «Полный архив (.json)» по-прежнему выгружает
персонажа вместе со всеми ветками, памятью и дневниками.

Проверить импорт можно на образцах из `samples/`: `mirra-card-v2.json`
(аккуратная карточка), `mirra-card.png` (она же, вложенная в PNG) и
`rosalia-dirty-card.json` — нарочно «грязная» карточка в стиле Chub: лист
персонажа блоками, changelog и ссылки в системных правилах. Все три файла
читаются тестами.

### Работа модели над карточкой

Карточек на английском большинство, а играете вы по-русски — поэтому в окне
импорта есть кнопки, которые отправляют карточку в модель. Ничего не происходит
само: запросы платные и идут только по нажатию, ход показывается прогрессом,
любой проход можно отменить.

| Кнопка | Что делает |
|---|---|
| **Перевести на русский** | Переводит всё содержимое: описание, характер, сценарий, правила, приветствия, примеры реплик и лорбук вместе с ключами-триггерами. Имена, клички, названия мест, рас и вымышленные термины **адаптируются** под русский (`Rosalia` → `Розалия`, `Ethralis` → `Этралис`, `Varamis, Varamis'а` → `Варамис, Варамиса`). `*действия*` и тире в диалогах сохраняются, характер и эротика не смягчаются, примечаний переводчика нет. Макросы `{{user}}`/`{{char}}` не переводятся и не ломаются. Уже русский текст модели не отправляется |
| **Привести в порядок** | Один проход: огромную карточку сначала **сжимает** → чистит остатки мусора (`{{user}}`/`{{char}}` заменяются именами, а не вырезаются) → **расставляет перепутанные поля** (характер во внешности и наоборот) и очищает поле, из которого содержимое уехало → дополняет подпись, жанр и теги |
| **Сжать раздутые поля** | Появляется только для очень больших карточек (больше 12 000 символов) и сжимает примерно на 40% только раздутые куски текста, сохраняя ключевые факты и язык оригинала |
| *Отдельные действия* | Свёрнутый блок для тонкой доработки: только очистить, только дополнить поля |

Модель ничего не выдумывает: дополнение работает лишь с пустыми полями и
только по фактам карточки — нет данных, поле остаётся пустым.

Длинные тексты режутся на части, пачки уходят параллельно (до трёх
одновременно), а модели сразу просится запас токенов на ответ. Частичный или
битый ответ не ломает импорт: применяется то, что дошло. Ответ не в том
формате переспрашивается один раз с жёстким напоминанием; пустой ответ от
провайдера — тоже повод переспросить, без ошибки на экране. Если модель так и
не вернула ни одного фрагмента (отказ, цензурный фильтр), импорт честно скажет
об этом вместо «перевод не потребовался».

### Что видно до импорта

Окно импорта построено по секциям и читается сверху вниз:

- **Шапка персонажа** — аватар, имя (редактируется прямо здесь), источник
  карточки и автор, жанр, подпись, содержимое (ветки, знания, факты, записи —
  показываются только если их больше нуля) и теги. Отчёт автоматической чистки
  сворачивается в строку «Текст карточки очищен автоматически» с подробностями.
- **Вкладка «Импорт»** — доработка моделью (главное действие «Привести в
  порядок», перевод, сжатие и отдельные действия — с пояснением под каждой
  кнопкой, прогресс-баром и отменой) и параметры импорта (чистка текста,
  история общения).
- **Вкладка «Карточка»** — лист персонажа в том виде, в каком он ляжет в базу:
  шапка с аватаром, жанром, тегами и счётчиком заполненных полей; внешность,
  характер, сценарий и системные правила — отдельными блоками; первое сообщение
  с ролевой разметкой; альтернативные приветствия (каждое подписано: станет
  свайпом первого сообщения) и записи мира с ключами-чипами. Пустые поля
  помечаются пунктиром и подписью «не заполнено» — сразу видно, чего не хватает.

Скриптовая чистка (без модели) дополнительно: убирает HTML, markdown-картинки
и невидимые символы; раскрывает мусорные побеги из JSON (`\\n`, одинокие
обратные слэши); выбрасывает changelog, рекламу и ссылки на внешние сервисы;
разбирает лист персонажа, записанный блоками `[Ключ: значение]`.

Детали реализации: `src/services/cardAi.ts` (проходы модели),
`src/services/characterCard.ts` (чистое преобразование данных),
`src/services/cardText.ts` (очистка текста и разбор блоков),
`src/utils/pngChunks.ts` (чтение и запись текстовых чанков PNG),
`src/utils/characterCardFile.ts` (файловые операции). Всё это покрыто
тестами `tests/characterCard.test.ts`, `tests/cardText.test.ts` и
`tests/cardAi.test.ts`.

### Как собирается промпт

Системный промпт строится слоями: неизменяемое ядро (мета-протокол и правила
формата) → паспорт персонажа и персоны игрока → поведенческие модули (темп,
речь, атмосфера) → долговременная память (синопсис, факты) → динамический хвост
(лотбук, шкалы, заметки режиссёра, вектор мыслей). Стабильный префикс позволяет
провайдеру кэшировать контекст. В групповой сцене в паспорт персонажа
добавляется блок «Групповая сцена»: список присутствующих с краткими
характеристиками, правило «отвечаешь только за себя» и правило треугольника —
игрок остаётся якорем сцены, а не пассивным зрителем. Блоки «Сценическое
присутствие» и «Взаимоотношения внутри группы» описывают, кто сейчас в комнате
(и почему остальные за кадром) и что герои думают друг о друге. Блок «Текущее
состояние отношений» показывает шкалы того, от чьего лица идёт ответ, а чужие
реплики в контексте помечаются именем автора. Там же — инструкция вернуть
персонажа в сцену: модель описывает появление и перечисляет имена в поле
`returned`, после чего чат автоматически снимает «за кадром». Обратная
операция — поле `left` с причиной: герой уходит по своим делам, а память
сцены (дневник, якоря, синопсис, хроника) учитывает весь состав группы,
хотя и ведётся от лица основного персонажа.

## Данные и приватность

- Персонажи, диалоги, память и настройки живут в IndexedDB браузера.
- API-ключ хранится там же и уходит только на выбранный вами сервер модели.
- Персоны лежат в том же хранилище и попадают в резервную копию автоматически.
- Экспорт бэкапа — один JSON-файл со всей базой (Настройки → Бэкап).
- Рекомендуется нажать «Защитить данные» в настройках: браузер пометит хранилище
  постоянным и не будет вычищать истории при долгом простое (особенно важно для
  Safari на iOS).

## Деплой

### Деплой из GitHub на Netlify (по шагам)

Всё нужное уже лежит в репозитории (`netlify.toml`, `netlify/edge-functions/`),
поэтому настраивать сборку руками не придётся.

1. Приведите код в ветку, которую будете публиковать (обычно `main`): влийте
   рабочую ветку через Pull Request. Можно и просто выбрать рабочую ветку
   production-веткой на шаге 4 — тогда деплоится она сама.
2. На [app.netlify.com](https://app.netlify.com) нажмите **Add new site →
   Import an existing project → GitHub** и дайте Netlify доступ к репозиторию.
3. Выберите репозиторий `nocturne-pwa`. Поля сборки подтянутся из
   `netlify.toml`: команда `npm run build`, каталог публикации `dist`,
   Node 22. **Base directory оставьте пустым** (репозиторий и есть корень
   проекта). Если поля пустые — впишите значения вручную.
4. Production branch — `main` (или ваша рабочая ветка). Нажмите **Deploy**.
5. Дождитесь окончания сборки и откройте сайт. Затем проверьте резервный
   прокси: `https://<ваш-сайт>/api/llm-proxy` должен вернуть
   `{"error":"Missing target parameter"}` с кодом 400 — значит edge-функция
   задеплоилась и RU OpenRouter будет работать.
6. В приложении: Настройки → Модель и API → шаблон **RU OpenRouter**, ключ →
   кнопка **«Проверить соединение»**.

Дальше каждый push в production-ветку Netlify пересоберёт сайт сам, а пул-реквесты
получат отдельные deploy preview со своими адресами.

Важно про данные: истории, персонажи, память и API-ключ живут в IndexedDB
браузера и привязаны к домену. На новом адресе они не появятся сами —
перенесите их бэкапом: на старом адресе Настройки → **Бэкап** → «Скачать
бэкап (.json)», на новом — «Восстановление» из этого файла.

### Вариант через Netlify CLI

Если удобнее из терминала: `npm i -g netlify-cli`, затем `netlify login`,
`netlify init` (подключит репозиторий) и `netlify deploy --build --prod`.

### Что делает `netlify.toml`

Edge-функция `netlify/edge-functions/llm-proxy.ts` подключается по пути
`/api/llm-proxy`. Для RU OpenRouter это основной same-origin канал, поэтому
браузер не делает прямой CORS-запрос; для других внешних провайдеров путь
остаётся резервным каналом при необходимости. Тот же путь поднимает и dev-сервер,
поэтому локальная разработка ведёт себя как продакшен.

Важно: каталог `dist` и `netlify.toml` должны попасть в деплой вместе —
визуальный drag-and-drop только `dist` edge-функцию не загрузит, и прокси
будет отвечать 404. В этом случае приложение прямо говорит, что дело в
прокси-канале, а не в «неверном URL».

## Известные ограничения

- Проверки живут в репозитории: `npm test` (vitest, 109 тестов) — мета-парсер,
  вызовы провайдеров, промпт-студия, персоны, групповые сцены и бэкап.
  `npm run verify` = типы + тесты + сборка; CI (GitHub Actions) гоняет то же
  самое на каждый push и pull request.
- Групповая сцена тратит два обращения к модели за ход: короткий запрос
  «кто отвечает первым» и сам ответ. Если говорящего выбрал игрок (кнопка над
  строкой ввода) или это локальный эндпоинт — обращение одно. Сбой роутера не
  ломает ход: говорящий выбирается по упоминанию имени и порядку состава.
- Если ход прервался (ошибка сети, «Стоп»), кнопка «Повторить запрос»
  дожимает только тех участников, кто ещё не ответил.
- Генератор группы сначала просит у модели один JSON со всеми героями. Если
  модель отвечает прозой или обрывается, запрос повторяется строже, а затем
  группа собирается по одному герою — это дольше по времени, но результат
  будет.
- Линтер не настроен.
- Таймаутов у запросов нет: медленная локальная модель может думать долго.
  Вместо ограничения по времени используется кнопка «Стоп».
- Переключение персоны в открытом чате меняет подпись прошлых реплик: имя
  берётся из текущей личности, а не хранится в сообщении.
- Ревайнд истории не откатывает шкалы, синопсис и дневник — память продолжает
  помнить удалённые сообщения. Оставлено осознанно, как привычное поведение.
- Мобильная навигация не менялась: «Память», «Дневники» и «Миры» открываются
  как раньше.
