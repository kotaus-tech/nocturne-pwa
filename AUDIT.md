## Свои личности (новое)

Раньше профиль игрока был один и его можно было только править. Теперь это
полноценный список персон.

| Что | Как |
|---|---|
| Хранение | KV-ключи `personas` и `activePersonaId`; схема Dexie не менялась, миграции нет |
| Первый запуск | старый одиночный профиль автоматически становится первой персоной |
| Совместимость | `getUserProfile()`/`setUserProfile()` работают с активной персоной, поэтому чат, промпты и старый ключ `userProfile` ведут себя как раньше |
| Бэкап | персоны попадают в резервную копию автоматически (таблица KV экспортируется целиком) |
| Интерфейс | список персон, активная карточка, создание, правка, дублирование, удаление с подтверждением; последнюю персону удалить нельзя |
| Применение | цепочка выбора: ветка чата (`ChatSession.personaId`) → карточка персонажа (`Character.defaultPersonaId`) → активная персона |
| Переключение | выпадающий список в левой панели и компактная кнопка в шапке чата; подпись «вы — Имя» рядом с именем персонажа |

### Ловушка Dexie, из-за которой переключение «не работало»

Симптом: после «Сделать активной» карточка и бейдж в панели обновлялись только
после перезахода в раздел.

Причина: `liveQuery` подписывается лишь на те чтения, которые идут из самой
функции запроса. Прежний `getActivePersonaId()` сначала ждал вложенный хелпер
`listPersonas()`, и только потом читал ключ `activePersonaId` — это чтение в
подписку не попадало, поэтому мутация ключа не перезапускала запрос.

Решение: `getPersonaState()` читает оба ключа KV напрямую, без вложенных
хелперов, и является единственной точкой для live-запросов; остальные функции
построены поверх неё. Поведение подтверждено тестом на настоящем Dexie с
fake-indexeddb: подписки срабатывают на переключение, правку и удаление персоны.

## Групповые сцены (новое)

Раньше ветка была жёстко «игрок + один персонаж». Теперь в сцену можно добавить
других персонажей библиотеки.

| Что | Как |
|---|---|
| Хранение | `ChatSession.characterIds` (дополнительные участники) и `ChatSession.participantStats` (их шкалы); схема Dexie не менялась, миграции нет |
| Привязка реплики | `Message.characterId` + `characterName` — снимок имени переживает удаление персонажа |
| Управление | Панель режиссёра → «Групповая сцена»: список сцены по порядку, добавление через выбор и удаление крестиком |
| Ход | По очереди, по одному запросу на участника. Следующий видит уже готовые реплики предыдущих, поэтому персонажи реально реагируют друг на друга |
| Контекст | Чужие реплики помечаются именем (`Мира: — …`), свои остаются без префикса — модель не путает, кто что сказал |
| Промпт | Блок «Групповая сцена»: кто присутствует, «отвечаешь только за себя», запрет говорить за игрока и подписывать свои реплики |
| Шкалы | У каждого участника свои: основного — в `currentStats`, остальных — в `participantStats`; тосты о переломных моментах показываются для основного персонажа |
| Интерфейс | Аватары и имена авторов в ленте и в режиме книги, счётчик сцены в шапке ветки и в списке веток, переключатель участника в «Аналитике отношений», инспектор контекста показывает промпт последнего говорящего |
| Сбой на середине | Кнопка «Повторить запрос» дожимает тех участников, кто не успел ответить |
| Экспорт ветки | Участники сцены едут в JSON-бандле (`participants`), при импорте чужие карточки не перезаписываются |
| Удаление персонажа | Он автоматически исчезает из чужих групповых сцен вместе со своими шкалами |

Осознанные ограничения: порядок задаётся списком (перетаскивания нет), каждый
участник — отдельный запрос, поэтому большая сцена расходует больше лимитов.

Тесты (`tests/group.test.ts`): санитайзеры новых полей, подпись чужих реплик,
сборка промпта сцены, порядок и состав участников, добор неответивших, чистка
связей при удалении персонажа.
