## A. Критические баги (ломают заявленный функционал)

### A1. Режим Google Gemini не работает полностью 🔴
В `src/services/apiClient.ts` (строки **772, 898, 1013, 1080**) URL собираются склеенными markdown-ссылками:

```ts
const url = `[https://generativelanguage.googleapis.com/v1beta/models/$](https://generativelanguage.googleapis.com/v1beta/models/$){model}:generateContent?key=${apiKey}`;
```

Проверено в Node: строка уходит в `fetch` как есть, браузер резолвит её **относительно текущего домена**:
`https://nocturne.app/[https://generativelanguage.googleapis.com/...]...`

→ Gemini-провайдер не работает ни в чате (`callGemini`, `callGeminiStream`), ни в генерации промптов картинок, ни в списке моделей (`fetchAvailableModels`). Затронуты 4 функции.

### A2. Пресеты подключения в настройках содержат нерабочий Base URL 🔴
`src/components/settings/SettingsPage.tsx:73,78`:

```ts
baseUrl: "[https://openrouter.ai/api/v1](https://openrouter.ai/api/v1)",
baseUrl: "[https://api.deepseek.com](https://api.deepseek.com)",
```

Нажатие пресета «OpenRouter» / «DeepSeek» подставляет мусорный адрес. Дальше `resolveEndpoints` делает из него `[https://...](https://...)/chat/completions`, fetch падает с `TypeError`, включается фоллбек на прокси, а edge-функция отвечает `400 Invalid target URL`. Итог: пользователь видит непонятную ошибку и не понимает, что сломался пресет.

### A3. Парсер мета-блока теряет мысли/статы и показывает JSON в чате 🔴
`src/services/metaParser.ts` берёт **первый** ```-блок в ответе и удаляет его:

```ts
const metaMatch = text.match(/```(?:meta|json)?\s*([\s\S]*?)\s*```/i);
...
text = text.replace(/```(?:meta|json)?[\s\S]*?```/i, "").trim();
```

Эмпирические прогоны (7 кейсов, реальные сценарии):

| Кейс | Результат |
|---|---|
| `meta`-блок в конце | ✅ ок |
| В тексте реплики есть **любой другой** код-блок | ❌ удаляется он, а `meta`-JSON **остаётся в тексте** и виден пользователю; статы/мысли не считаны |
| Модель забыла ```` ``` ```` у JSON | ❌ сырой JSON в пузыре сообщения |
| Валидный блок, но битый JSON (висячая запятая) | ❌ **тихий провал**: блок вырезан из текста, статы и мысли потеряны, ошибки пользователю не показывают |

Поскольку от стат-протокола зависит вся механика отношений (тосты, статусы, память), тихие потери здесь = «персонаж перестал развиваться», без диагностики.

**Как чинить:** парсить последний блок, искать по префиксу `meta`, иметь fallback на «JSON без фенсов» (поиск последней `{...}` в конце), и не вырезать блок из текста, если JSON не распарсился.

### A4. PWA не работает офлайн (и это заявлено как PWA) 🔴
`public/sw.js`:

```js
const CACHE_NAME = "anima-rp-v2";        // легаси-брендинг, переменная не используется
install → ничего не кэшируется
activate → удаляет ВСЕ кэши
fetch → fetch(request).catch(() => caches.match(request))
```

`caches.match()` всегда промахивается, потому что кэш никогда не наполняется. При потере сети приложение не открывается вообще. При этом вся идея приложения — «local-first офлайн-блокнот для историй».

Дополнительно: `skipWaiting()` на install без управления версиями; нет стратегий (stale-while-revalidate для медиа, cache-first для оболочки); нет уведомления «доступно обновление».

### A5. Фоллбек-прокси фактически не работает 🔴
`netlify/edge-functions/llm-proxy.ts` разрешает ровно один хост:

```ts
const allowedHosts = ["api.ru-openrouter.ru"];
```

В проекте больше нет **ни одного** упоминания `ru-openrouter` (ни в пресетах, ни в дефолтах, где `openrouter.ai`/`deepseek`). То есть при CORS-блокировке (типичный кейс для OpenRouter/DeepSeek из браузера) запасной путь всегда отдаёт `403 Host not allowed`, а `formatApiError` покажет это как «Доступ запрещён. Проверьте права ключа» — пользователь пойдёт менять рабочий ключ.

### A6. Нет запроса постоянного хранилища → риск потери всей библиотеки 🔴
`navigator.storage.persist()` нигде не вызывается, состояние квоты не отслеживается. На Safari/iOS IndexedDB для сайта вычищается после ~7 дней без визита, если хранилище не помечено как persistent. Для приложения, где вся библиотека персонажей и переписок живёт в IndexedDB, а бэкап — ручное действие в настройках, это самый дорогой возможный баг.

## B. Функциональные баги и логические дыры (P1)

### B1. На мобильных недоступны «Память», «Дневники» и «Миры (Lorebook)»
`BottomNav` — только 5 табов (Главная/Чаты/Персонажи/Персона/Настройки), а левый сайдбар с остальными разделами — `hidden lg:flex`. Своего меню/гамбургера нет. «Память» и «Дневники» иногда достижимы из виджетов на главной (только если есть данные), а **страница Lorebook недостижима на телефоне вообще**.

### B2. Хардкод в карточке истории на главной
`HomePage.tsx` (`StoryCard`): рядом с именем персонажа выводится статичное `1` — видимо, остаток от «непрочитано/индекс». Реального смысла не несёт, выглядит как баг.

### B3. Несогласованные тексты и заглушки на главной
- «Вся библиотека (N)» → открывается страница, а на главной показываются только `allCharacters.slice(0, 8)`.
- Фоллбэки имени: `«Странник»` в сайдбаре/дефолте БД, но `«Алекс»` в виджете персоны.
- Виджет «AI профиль сохранён: **dexie**» — служебная строка без пользы для пользователя.
- Фильтр жанров на главной сравнивает строки точно (`===`), тогда как поиск нормализует регистр/ё.

### B4. Иконки и манифест PWA
| Факт | Проблема |
|---|---|
| `public/icons/icon-512.png` = **1408×1408, 2.30 МБ** | заявлено как `512x512` → рассинхрон размеров; иконка грузится при установке, занимает половину веса приложения |
| `purpose: "any maskable"` одной записью | на Android иконка обрезается по маске и «плывёт»; нужны отдельные записи |
| Нет `192×192` | плохое качество иконки на домашнем экране Android |
| Нет `"id"`, `"lang": "ru"`, `"screenshots"`, `"shortcuts"`, `"categories"` | теряется бонус к установке в Chrome, нет быстрых действий |
| `apple-touch-icon` = та же 2.3 МБ PNG без 180×180 | тяжёлая загрузка в iOS, нет `apple-mobile-web-app-title` |
| `orientation: "portrait"` | на десктопе/планшете принудительная ориентация |

### B5. Установка и обновление приложения не предусмотрены
Нет обработки `beforeinstallprompt` (своей кнопки «Установить»), нет UI «доступно обновление / обновить», нет `registration.update()`, нет версии сборки в настройках.

### B6. Дефолтный провайдер не консистентен с прокси и документацией
`DEFAULT_API_CONFIG.baseUrl = "https://openrouter.ai/api/v1"`, а прокси знает только `api.ru-openrouter.ru` (см. A5). Плюс у OpenRouter есть обязательные для них `HTTP-Referer`/`X-Title` — не отправляются.

### B7. Рассинхронизация «памяти» и истории
- `rewindToMessage` (удаление сообщения и всего после него) **не откатывает** `currentStats`, `summary`, `storyLog`, `diary`, `extractedFacts` — «память» продолжает помнить то, чего в истории уже нет.
- Регенерация ответа добавляет новый `swipe`, но `session.currentStats` безусловно перезаписывается последней генерацией: при переключении на первый свайп текст старый, а статы от второго.
- Авто-извлечение памяти триггерится по счётчику `allMessages.length + 1` каждые 12 сообщений; после ревайнда/удаления счётчик может «не дойти» или сработать повторно; сам вызов `compressMemory()` не отменяется при размонтировании и не блокирует повторный запуск.

### B8. Нет отмены генерации и нет защиты от параллельных запросов
`AbortController` не используется нигде. Кнопки «Продолжить»/«Подсказки»/«Регенерация» защищены только флагом `sending`, но:
- нет кнопки «Стоп», нельзя прервать длинный ответ (важно для локальных моделей, где ответ идёт минутами);
- нет таймаута запроса — при «подвисшем» соединении `sending=true` навсегда, пока не сработает сетевой таймаут браузера.

### B9. Блокирующие системные диалоги
8 мест с `confirm()`/`prompt()` (удаление ветки, переименование, стирание всех данных, импорт-бэкап, удаление пресета). В standalone-режиме PWA это выглядит чужеродно, а `prompt` для переименования ветки не работает в некоторых вебвью; кастомного `ConfirmDialog` в проекте нет (при этом `Modal` сделан очень аккуратно: focus-trap, `inert`, возврат фокуса — на нём и надо делать).

### B10. Медиа: неограниченные картинки в IndexedDB
- `DirectorPanel.handleFileUpload` читает **любой** файл в base64 data-URL и пишет в `session.wallpaperUrl`. Фото с телефона = 5–10 МБ base64 внутри записи Dexie → раздувание БД, тормоза live-query, риск `QuotaExceededError` посреди работы.
- `Avatar`/аватар персонажа проходят через `ImageCropperModal` (512px), а обои — нет: нет ни ресайза, ни проверки размера, ни лимита.
- Квоты/оценки (`navigator.storage.estimate()`) нет; пользователю не показывают, сколько занято.

### B11. Дублирование и мёртвый код
- 4 почти одинаковые реализации вызова OpenAI-совместимого API + 2 Gemini-реализации в одном `apiClient.ts` (1152 строки).
- `stripMeta` продублирован в 3 файлах, `fileToDataUrl` — в 3, «безопасный парсинг JSON от LLM» — в 3 разных вариантах.
- Полностью мёртвые модули и функции: `BackupPage.tsx` (428 строк, заменён вкладкой в настройках), `ProgressBar.tsx`, `pollinations.generateSceneImageUrl` (вся интеграция с Pollinations не вызывается — `message.imageUrl` нигде не заполняется и не рендерится), `requestSummary`, `importChatSession`, `toggleCharacterPin`, `onFavoritesOnlyChange` (передаётся и не используется).
- 10 файлов `*.bak.*` (4326 строк) лежат в `src/` и попадают в компиляцию TypeScript.

## C. Архитектура и производительность (P2)

1. **Перерисовка всего чата на каждый чанк стрима.** `setLiveStreamedText(chunk)` меняет состояние `ChatView` (1507 строк, всё дерево сообщений) ~30–60 раз в секунду. `MessageBubble` не обёрнут в `React.memo`, у `TypingBubble` включён framer-motion `layout`. На длинных ветках (100+ сообщений, мобильный CPU) это ощутимые лаги.
2. **God-компоненты.** `ChatView` = данные + сеть + парсинг + скролл-логика + 6 модалок + вёрстка. `SettingsPage` = API + пресеты + бэкапы + вёрстка. Нет слоя хуков (`useSession`, `useChatStream`, `useSettings`).
3. **Single-file сборка.** `vite-plugin-singlefile` инлайнит всё в `index.html`: нет разделения чанков, нет long-term-кэширования (при каждом деплое пользователь тянет 978 КБ заново), и это прямо конфликтует с идеей офлайн-PWA (один большой файл вместо кэшируемых ассетов).
4. **Нет истории навигации.** Разделы — это `useState` в `App.tsx`; кнопка/жест «назад» в браузере и в PWA не закрывает чат и не возвращает на предыдущий экран, deep-link невозможен.
5. **Тайпинг-эффект.** `isBrandNew` считается как `Date.now() - message.timestamp < 4000` при каждом рендере (замыкание на «текущем» времени), начальное состояние берётся в `useState` — при перемонтировании (например, при раскрытии ещё страницы сообщений) старые сообщения могут «печататься» заново.
6. **Lorebook.** `activateLorebook` смотрит только 3 последних сообщения и ищет примитивным `includes()`: «город» активируется на «огород», записи по персонажу/сцене не триггерятся, при росте базы будет шум. Нет учёта `keys` из персоны игрока и режиссёрских заметок.
7. **`cleanStreamTextForUI`** обрезает текст регуляркой `/```(?:meta|json)?[\s\S]*$/` — при разрыве токенов (` ` ``` ` ` может прийти как `` ` ` `` + `` `` `meta` ``) в UI мигает обрывок, а легитимный код-фенс в реплике вырезается целиком.
8. **Контекст и KV-кэш.** «Ступенчатое окно» (`getSliceForContext`) создаёт окно `contextWindow + 0…9` сообщений — ок, но `contextWindow` по умолчанию 24 сообщения, а UI настроек предлагает значения 2048…131072 (это похоже на токены, а не сообщения) → путаница в семантике поля.
9. **`uuid`** при живом `crypto.randomUUID()` — лишняя зависимость для PWA.
10. **Контрастность.** `--text-muted #677186` на фоне `#090b10` = **4.01:1**, `--text-placeholder #5d677c` = **3.46:1** — ниже требований WCAG AA (4.5:1) для мелкого текста, а мелкого текста в UI много (10–11px подписи, подзаголовки). Остальные токены в норме (primary 17.8:1, secondary 8.05:1, accent 4.65:1).
11. **Доступность.** Из 222 кнопок только ~38 имеют `aria-label`; карточки-персонажи сделаны `role="button" tabIndex={0}` (теряется семантика списка); в `InputBar` Enter **не отправляет** сообщение, если браузер считает устройство «touch» (`pointer: coarse`) — на планшете с клавиатурой или ноутбуке с тачскрином отправка мышью по Enter ломается.
12. **Мелочи UX:** текст черновика в `InputBar` теряется при выходе из чата; нет индикатора «сохранено» при правке сообщения; `URL.revokeObjectURL` вызывается синхронно сразу после `link.click()` (Safari может прервать скачивание), в настройках `link` не удаляется из DOM; при `novelMode` кнопка «вниз» ведёт себя иначе, чем в чате (скачок на `scrollHeight` вместо smooth-прокрутки к последнему сообщению).

## D. Качество кода и репозиторий (P2)

1. **`npm run build` не проверяет типы** (`vite build` без `tsc`). Итог — 34 ошибки TypeScript в коде, включая `TS18048` (возможный `undefined`) в `ChatView.bak.tsx` и `TS6133` по неиспользуемым импортам в 15+ файлах. Нет скриптов `typecheck`/`lint`.
2. **Нет ни одного теста** и ни одной тестовой библиотеки, при том что самая рискованная часть проекта — парсеры ответов LLM (`metaParser`, `memoryEngine.safeParseJson`, `characterGenerator.safeParseJson`, `parseSuggestionsFromRaw`) — чистая логика, которую тривиально покрыть.
3. **Нет ESLint/Prettier** — стиль держится только на дисциплине (в целом он ровный: `type="button"` есть у всех 222 кнопок, `console.log` нет, `dangerouslySetInnerHTML` не используется — это плюс).
4. **Репозиторий:** нет `README.md`, `LICENSE`, `.github/` (CI), `CONTRIBUTING`. `.gitignore` не покрывает `.netlify/` — в git уже лежат артефакты сборки edge-функций (`*.eszip`, `*.tar.gz`, `state.json`, `manifest.json`). В корне пустой файл `Текстовый документ.txt` (0 байт). `deno.lock` лежит без deno-конфигурации/скриптов.
5. **`package.json`:** имя `react-vite-tailwind`, версия `0.0.0`, нет `engines`, нет `packageManager`, нет `typecheck`/`lint`/`test`/`format`.
6. **Деплой:** в `netlify.toml` нет `[build]` (`command`/`publish`) и нет заголовков безопасности (`[headers]` с CSP, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`). Если сборка настроена только в UI Netlify — это не воспроизводимо из репозитория.
7. **`index.html`:** нет Open Graph/Twitter-мета (красивый шер в мессенджере), нет `apple-mobile-web-app-title`, нет `<noscript>`, `color-scheme` объявлен только в CSS.

## E. Безопасность и приватность

1. **API-ключ хранится в открытом виде в IndexedDB** (`kv → apiConfig.apiKey`) — для local-first это ожидаемо, но стоит явно предупредить пользователя в UI и предусмотреть вариант «не сохранять ключ» (только на сессию, в `sessionStorage`).
2. **Ключ уходит на сторонние хосты:** edge-функция `llm-proxy` принимает `target` из query и прозрачно прокидывает `Authorization` — если пользователь подставит свой домен в allow-list, ключ будет ходить через чужой edge. Стоит ограничить прокси только хостами из UI-списка и логировать отказы на сервере.
3. **Нет CSP** и любых security-заголовков (см. D6) — при XSS (инъекция в текст персонажа? сейчас `dangerouslySetInnerHTML` не используется, это хорошо) ключ и вся переписка утекают одним запросом.
4. **Внешний бесплатный генератор картинок Pollinations** (`image.pollinations.ai`) — запросы с текстом сцены уходят третьей стороне; сейчас код не вызывается, но модуль в проекте есть и запрашивает `&nologo=true` в обход правил сервиса.
5. **`confirm`-импорт бэкапа** полностью перезаписывает базу без снапшота «до импорта»: импорт не того файла = мгновенная потеря текущих данных (откат только вручную, если пользователь делал экспорт).

## F. Что сделано хорошо (чтобы не потерять при рефакторинге)

- Продуманная **система дизайна** (`index.css`: токены, состояния, safe-area, reduced-motion, кастомные скроллбары) — сильная и целостная.
- **`Modal`** — уровень продакшена: focus-trap, `inert` для фона, стек модалок, возврат фокуса, корректная работа с `overflow` документа.
- **`clipboard.ts`** — аккуратный фоллбек с восстановлением выделения и фокуса.
- **`ambientEngine`** — процедурный звук без файлов, `useSyncExternalStore`, корректный teardown, LFO для ветра, потрескивание для костра. Отличная идея и хорошая реализация.
- Аккуратные **санитайзеры данных** в `db.ts` (импорт битых бэкапов не роняет приложение), экспорт/импорт ветки и персонажа с предпросмотром.
- Нормализация поиска (`ё→е`, `Intl.Collator`) в библиотеке персонажей.
